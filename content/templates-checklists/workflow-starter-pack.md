Choose a bundle when one workflow rule is already set and several records or recurring actions must work together around the same stage. If one template or checklist solves the immediate problem, open that resource directly from [Templates and checklists](/templates-checklists/).

If you cannot name the affected stage, use the [Workflow diagnostic checklist](/templates/workflow-diagnostic-checklist/) first. If the entire client lifecycle is unclear, start with [Freelance client workflow system: inquiry to final payment](/workflows/freelance-client-workflow-system-inquiry-to-final-payment/).

## Confirm the trigger before using a bundle

- For setup, confirm the agreement or authorization required for the project and its start conditions.
- For delivery, identify the milestone, review owner, and acceptance rule.
- For billing, use the invoice trigger and follow-up terms in the applicable agreement.
- For closeout, record the final delivery, approval, billing, access, and archive states that apply.
- For stack cleanup, decide which operating model the remaining tools must support.

Do not import a sample sequence as a contract term or universal cadence. Adapt each resource to the service, agreement, jurisdiction, workload, and tools involved.

## Use only what the stage requires

A bundle is a menu, not a requirement to use every item. Choose the resources that correspond to current triggers and records. Record who owns each one and where its result belongs.

For an ambiguous client response, use [FAQ: what counts as client approval?](/faq/what-counts-as-client-approval-before-billing-or-next-stage/). For a closeout request with no response, use [Client not responding at project closeout](/faq/what-to-do-when-client-does-not-respond-to-project-closeout/).

## Finish with one named next action

After completing a resource:

1. save its result in the authoritative project record;
2. name the next action and owner;
3. update any affected date, approval, billing, or closeout state;
4. open another resource only when the next trigger requires it.

The bundle has done its job when the current stage has a usable record and a named next action, not when every linked resource has been opened.
