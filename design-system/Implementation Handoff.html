Section 03

Implementation order

Land changes in this sequence. Each step assumes the prior step is settled, mirroring the order the kit was built. Do not interleave; finish a step, build, eyeball the diff, then start the next.

  1. Read the repo's own instructions first. Open AGENT.md and TRACKER.md at the repo root. Open .claude/skills/soloopsguide-agent/SKILL.md if present. Don't bulk-read other docs.
  2. Inspect current templates. Targeted reads of layouts/index.html, layouts/_default/{single,list,taxonomy,terms,search}.html, layouts/404.html, and the partials above. Note current markup, classes, and any inline JS hooks.
  3. Tokens and typography. Update the :root token block in static/css/main.css to match the kit's values. Add the Source Sans 3 + Lora font link in layouts/partials/head.html only after fallback validation (Section 05). Don't change layout markup in this step.
  4. Header + mobile nav. Rewrite layouts/partials/header.html to remove "Workflows" from the nav list, promote it to the CTA, add [data-nav-toggle] + ARIA. Add the matching toggle handler in site-script.html. Verify open/closed states at 375 / 768 / 1080 / 1280.
  5. Homepage + hub patterns. Update layouts/index.html for the hero / chooser / value-prop layout. Update layouts/_default/list.html for hub structure: section hero grid, reading-paths shortcode, journey-note, page-count stat, priority/supporting split.
  6. Article + template patterns. Update single.html for the article header grid + aside (use-for, section-hub, tags, best-next, page-type), reading-layout body, page-type-block utility panel, related panel. Wire the template-section branch for the copy/print article-actions toolbar.
  7. Comparison + blueprint patterns. Extend single.html (or add section-specific layouts under layouts/workflow-comparisons/ / layouts/software-stack-blueprints/) for ModelCard groups, criteria matrix, BestForBlock, DecisionShortcut, PrincipleList, BlueprintTier, SetupSequence, NextStepLinkBlock. Reuse the existing page-type-block with the comparison / blueprint variants.
  8. Glossary + FAQ patterns. Hub variants in list.html (term grid, FAQ list); single variants in single.html (term definition, FAQ answer) with their utility + related panels.
  9. Trust + search + 404. Wire the no-pages branch of list.html for trust/prose pages (slim 2-card aside, plain related list, callout). Update layouts/_default/search.html for the type-filter tabs + result rows. Rewrite layouts/404.html for the recovery layout.
  10. Taxonomy + tags index. Wire layouts/_default/taxonomy.html for the per-tag cross-cluster index. Wire layouts/_default/terms.html for the alphabetical master index. Add the tag-chips row to the article aside, pulling from tags: front matter, with the 2–3 chip cap and empty-row omission.
  11. Final QA / build. hugo --gc --minify clean. git diff --check clean. Walk Section 07 checklist. Verify sitemap, RSS, and canonicals are unchanged.
Section 04

Production constraints

Read these first

  • AGENT.md — repo conventions, branch + commit policy.
  • TRACKER.md — what's in flight, what's intentionally deferred.
  • .claude/skills/soloopsguide-agent/SKILL.md if present — narrower repo-specific instructions take precedence over this handoff.

Discovery discipline

  • Targeted file reads only. Open the files mapped in Section 02; don't sweep layouts/.
  • Avoid broad grep / search across the repo. Use precise paths.
  • Don't blindly read every doc. Read the three above, then work from the kit.

Preserve in production

  • URLs, slugs, aliases.
  • Front matter shape (tags, hub_priority, dates, etc.).
  • SEO metadata, canonical URLs, robots, sitemap behavior.
  • Pagination if already wired on long hubs.
  • Existing content — no copy edits in this pass.
  • Hugo shortcodes, including reading-path.
  • Production content patterns not in the UI kit (Section 08 lists them).

Do not introduce

  • Any mention of AI, automation, model names, or assistants in content, comments, commit messages, or tracker entries.
  • Fake authors, fake testimonials, fake reviewer counts, fake credentials, padded statistics.
  • Dark mode. The site has none and is staying that way.
  • Heavy JavaScript. Tiny vanilla-JS toggle only; no framework, no bundler.
  • New build steps, preprocessors, or Tailwind in production.
  • External icon CDNs. Icons stay inline SVG + Unicode glyphs.
Boundary

If a kit pattern requires changing a URL, removing a shortcode, or adding a JS framework to land, stop and flag it. The kit defers to production on routing, content, and runtime surface area.

Section 05

Typography decision

The kit standardizes on Source Sans 3 for UI and Lora for prose. Production currently ships system fonts only; the move to webfonts is conditional on the validation step at the bottom of this section.

RoleFamilyFallback
Headings, nav, buttons, labels, metadata, tablesSource Sans 3"Segoe UI", "Helvetica Neue", Arial, system-ui, sans-serif
Article prose, blockquotesLoraGeorgia, "Iowan Old Style", "Palatino Linotype", serif
Code / monospace—"SFMono-Regular", Consolas, "Liberation Mono", monospace

Loading rules

  • If webfont loading is deferred in this pass, ship the system fallback stack and stop. The fallback is intentionally editorial-credible on its own — Segoe UI / Helvetica Neue for UI, Georgia for prose.
  • Only load required weights. Source Sans 3: 400, 500, 600, 700. Lora: 400, 400 italic, 600. Do not load the full variable axes.
  • Use font-display: swap on every @font-face. The site must render legibly with system fonts during the swap window.
  • Self-host via google-webfonts-helper rather than the Google CDN — GDPR, latency, and cache consistency on Cloudflare Pages.
  • Preload Source Sans 3 woff2 in <head> (the 400 + 600 cuts only). Skip preload for Lora — it appears below the fold for most page views.

Validate before committing the font change

  • Mobile reading at 375px — article prose stays at the 16.75px / 1.9 line-height target without overflow.
  • Tables — the criteria matrix and category-decision tables remain legible at the comparison/blueprint widths; no horizontal scroll except inside the intentionally scrollable wrapper.
  • Metadata — meta pill row + small/meta sizes (12–14px) stay crisp; Source Sans 3 must hold legibility at 12px.
  • Article prose — Lora 400 in body, 400i in emphasis, 600 in lead/blockquote. Verify with a long workflow article and a long blueprint.
  • CLS — preload pass shows no layout shift on the hero h1 above the fold.
Section 06

Components and patterns to preserve

These are the patterns the kit has explicitly designed for. Production already has most of them. Do not remove or simplify any of them in pursuit of a cleaner diff.

Article surface

  • Reading paths ({{< reading-path >}} shortcode).
  • Article aside utility panel (page-type-block).
  • Related panel ("Continue the system").
  • Article tag chips row (2–3 chips, front-matter-driven, omitted when empty).
  • Template article-actions toolbar (copy-as-text + print).

Comparison + blueprint

  • Comparison table (criteria matrix, horizontally scrollable wrapper).
  • Decision criteria panel.
  • Best-for / Not-best-for two-column block.
  • Decision shortcut callout.
  • Blueprint tier cards (Starter / Stable / Scaling) with "Avoid for now" footer.
  • Setup sequence (numbered, with inline next-page links).
  • Next-step-by-outcome link block.

Hub, glossary, FAQ

  • Journey-note "Start here" block.
  • Section-stat page-count block.
  • Section-featured-link priority/recommended link.
  • Priority pages + supporting pages split on hubs.
  • FAQ list rows with Q badge.
  • Glossary term grid (2-col).
  • Checklist / template body blocks.

Site-level surfaces

  • Search results page (input + type filter tabs + result rows).
  • Trust / prose pages (slim 2-card aside, plain related list, sparing TCallout).
  • 404 recovery links (search + 4 cluster cards + narrow glossary/FAQ row).
  • Individual tag listing (/tags/<slug>/) grouped by page type, with adjacent-tag chips + hub rail.
  • /tags/ master index — alphabetical, page counts, short hints, hub rail.
  • Sparse / thin tag safeguards: omit tags with < 2 pages from the master index; never render "Nothing here yet."
Section 07

Validation checklist

Walk this list after the final commit lands and before pushing to main. Each item is a discrete check; treat any failure as a blocker.

Build & diff

  • hugo --gc --minify exits 0 with no warnings about missing layouts or partials.
  • git diff --check passes (no whitespace or merge-conflict artifacts).

Page renders

  • Homepage renders with hero, chooser, value props, footer.
  • Each cluster hub renders (Client Workflow Systems, Software Stack Blueprints, Workflow Comparisons, Templates & Checklists, Glossary, FAQ).
  • A representative article page renders with full aside (use-for, section-hub, tags, best-next, page-type), utility panel, related panel.
  • A template / checklist page renders with the article-actions toolbar.
  • A comparison page renders with model cards, criteria matrix, best-for block, decision shortcut, next-step block.
  • A blueprint page renders with principles, tiers, category table, setup sequence.
  • A glossary hub and a glossary term render.
  • An FAQ hub and an FAQ article render.
  • A trust / About page renders via the no-pages branch with the slim aside.
  • Search page accepts a query and renders results + filter tabs (or an empty state).
  • A deliberately bad URL hits layouts/404.html and shows the recovery layout.
  • A single tag page (/tags/<slug>/) renders, grouped by page type, with adjacent tags + hub rail.
  • /tags/ master index renders with alphabetical groups, page counts, and hub rail.

Interactions

  • Article aside tag chips route to the correct /tags/<slug>/ pages.
  • Articles with no tags: front matter omit the Tags row entirely (no empty header).
  • Mobile nav: hamburger opens, "X" closes, Esc closes, resizing past 820px closes; aria-expanded mirrors state; focus ring visible on the toggle.
  • Header search submits to /search/?q=… at every breakpoint.
  • 404 search reuses the same form pattern; recovery cards keyboard-navigate correctly.

Layout & assets

  • No horizontal overflow at 320 / 375 / 768 / 1080 / 1280 / 1440.
  • No broken images. Feature-image fallback path renders correctly when WebP is missing.
  • No placeholder href="#" links anywhere outside intentional anchors.
  • No console errors on the homepage, a representative article, comparison, blueprint, and 404.

SEO & routing

  • /sitemap.xml and /robots.txt diff to zero (or only to expected additions for the new tag/term pages).
  • Canonical URLs on representative pages match production conventions; no canonical regressions on hub or taxonomy pages.
  • RSS feeds (site, per-section, per-tag if enabled) still render valid XML.
  • Aliases / redirects defined in front matter still resolve.
Section 08

Known caveats

  • Print stylesheet is optional in this pass. If the existing print rules in main.css still hide header / aside / nav / related panel cleanly, leave them. Don't redesign print here.
  • Back-to-top button is optional. The kit doesn't require it. If production already renders one via site-script.html, preserve it; otherwise don't add it.
  • Analytics tracking attributes (data-track on links, etc.) are implementation-specific and stay out of scope for the kit. Preserve the existing attributes; do not redesign the tracking pattern.
  • Real WebP feature images in static/images/features/<cluster>/<slug>.webp are a separate production asset task. The kit defines the slot; production owns the source files.
  • Pagination on long hubs must be preserved if already present. If a hub paginates today, it must paginate after this pass with the same URL pattern.
  • RSS-per-tag and sitemap behavior are Hugo-native concerns. Do not redesign them in the UI kit; handle them carefully in the templates and verify with the Section 07 routing checks.
